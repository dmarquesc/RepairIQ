            SXM KNOWLEDGE BASE

            Failure patterns and repair intelligence

            The RepairIQ Knowledge Engine v0.1 contains four canonical SXM failure patterns. Each pattern produces seven structured outputs when matched by the engine. All outputs are technician decision support only.

            001

            HMC BIST / Initialization Failure

            GPU Host Management Controller failed Built-In Self Test during platform initialization. Heartbeat loss, HMC retry, and INIT failure signals. Downstream stages blocked. Highest-confidence SXM failure pattern.

            SXM-KE-001 94% confidence
            002

            PCIe Link-Width / Connectivity Failure

            PCIe link or width-related failure during fault localization. May indicate seating, slot damage, connector contamination, or GPU PCIe interface failure. Configuration must be ruled out before physical action.

            SXM-KE-002 87% confidence
            003

            Tester / Test Execution Failure

            Test environment execution failure. Tester calibration expired, script permission error, or execution abort. Hardware diagnosis must not proceed until tester validity is confirmed on a validated tester.

            SXM-KE-003 81% confidence
            004

            Firmware Compatibility / Mismatch Failure

            Firmware version mismatch or compatibility conflict. Requires validation against the approved compatibility matrix. Firmware updates require qualified technician supervision and documented approval.

            SXM-KE-004 78% confidence
            RULE TRANSPARENCY

            How the Knowledge Engine reasons

            The Knowledge Engine fires deterministic rules against confirmed analysis state. It does not hallucinate, predict, or recommend actions beyond the defined rule set. Every output carries a provenance record.

            PROTOTYPE ENGINE
            01 Receive Analysis

            Engine reads state.currentAnalysis after analyzeLog() completes.

            →
            02 Match Pattern

            matchFailurePattern() scores each of the four patterns against analysis conditions.

            →
            03 Build Outputs

            Seven structured outputs are built from the matched pattern and analysis state.

            →
            04 Render + REX

            Outputs are rendered into the extension mount. REX reads from engine output to answer queries.
